# 店家端驗收紀錄（N33）

驗收日期：2026-10-16，台灣時間。基準版本 N32；修正版 N33。

## 結論
本輪確認正式店家登入可使用，完成下列操作並修正四項顯示／效率問題。不能據此宣告所有手機、平板或背景推播驗收合格：操作環境是遠端 Chrome，沒有實體 iPhone／Android／平板的鍵盤、觸控與背景待機證據。正式測試訊息已寫入聊天，但手機提醒尚未確認，因此通知項目仍未通過。

## 本輪修正
1. 設計師管理、功能開關原本顯示通用省略號，改為人員與設定圖示。
2. 照片元件原本移除欄位標題，造成封面與大頭貼難以辨識；保留原欄位標題。
3. 群發進度原本將訊息寫入與推播完成混在一起。新增「聊天室已寫入」與「手機提醒尚待確認」數量，保留原傳送成功／待處理結果，不將未確認推播偽裝成成功。
4. 群發監看原本即使進度不變，也每五秒寫入雲端。改成只在進度改變時寫入；離開頁面停止舊畫面更新，避免返回時舊任務覆蓋目前畫面。

- 登入後重新載入，仍維持店家登入。最初原分頁顯示舊版入口，重新載入後顯示目前常用訊息／功能開關／設計師管理。
- 客戶管理：女生分類、切回全部、搜尋驗收帳號成功。
- 顧客資料：驗收帳號備註儲存成功，再次開啟確認保留。
- 標籤庫：建立「驗收專用」，儲存成功；套用驗收帳號後顯示 1 位。
- 群發：依驗收專用標籤選出 1 位，預覽並確認；B01 文字只送驗收帳號。聊天室顯示已送出，但手機提醒仍未確認。
- 一對一聊天：D01 文字由待傳轉為已送出；手機提醒仍未確認。
- 對話操作：稍後處理、待回覆篩選、取消待處理成功；取消後恢復原狀。
- 聊天工具：常用訊息 12 則可見，選用後只帶入草稿，未直接發送；草稿已清空。
- 已讀：進入驗收對話後，內部 3 則未讀標記消失。其他正式客人的未讀未被操作。
- 功能開關：手動已讀設定目前關閉。未更改全店已讀策略。
- 設計師：小刀、Nana 啟用，頁面明確說明不指定保留。
- 自動回覆：營業／非營業／休假與關鍵字規則均可讀取；未更改正式回覆內容。時段回覆會優先於關鍵字回覆。

- 新客審核、客人回報：目前空清單顯示正常，未對正式客人做核准、封鎖、刪除或合併測試。

## 自動化及模擬壓測
- npm test 通過；另新增 admin-report 測試通過：推播與訊息進度分開、無變化不重複寫雲端、隱藏頁不更新。
- npm run test:readiness 通過。
- 100／200／300／400 位收件者，每人兩張圖加一則文字，共 300／600／900／1200 筆唯一提交與模擬通知。
- 測試斷線、重新開啟、伺服器回應遺失後重試與防重複；本機峰值佇列 3.72 MiB。
- 配額不足時新批次全部回滾，不產生半批傳送。
- 200／300 筆模擬自動回覆並行隔離與去重，以及新客通知授權／去重通過。
- 這些是隔離模擬壓測，不是對正式 400 位客人群發，也不能代表 Firebase／FCM 的正式容量保證。

- 本輪沒有讓每一項正式設定都寫入並改回；避免覆蓋店家正在使用的資料。上述明確區分讀取、編輯取消與真正儲存。
- 未完成實體手機推播、桌面角標、鎖屏、長時間背景、鍵盤遮擋與觸控滑動驗收。

- 登入後部分舊客人分頁及開發記錄受到瀏覽器憑證保護限制，無法在本輪直接查看客人端收到 B01／D01 的畫面或量測雙向延遲。
- 本輪沒有正式上傳圖片群發；兩圖一文已做隔離壓測，但真實相簿／系統檔案選擇器與下載仍需要手機實測。
- 所有品牌尺寸及耗電量不可由遠端桌面瀏覽器證明。仍需 iPhone、Android 及平板各自驗收。

## 建議
- 先完成一支 iPhone 和一支 Android 的雙向推播實測，再開放大量客人。
- 商品實際填入護髮、造型等分類；目前皆為其他商品，分類功能無法提供實質導覽。
- 本月主打標題可改成明確服務名，例如頭皮去角質，讓詢問文字更清楚。
- 保留驗收專用標籤與測試帳號，用於後續版本驗收；不要對全體客人發測試訊息。
